# Embroidery Helper Refactor — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Same functionality and data, no blocking load, faster, clean file structure.

**Architecture:** Vanilla Node http server split into modules + vanilla JS frontend as ES-modules. 315 per-block JSON files merged into one `data/scheme.json` (1 request instead of 315 sync XHRs). Event delegation + debounced saves on the frontend.

**Tech Stack:** Node built-in `http`, vanilla JS (ES modules), Font Awesome 5.15.4 (vendored). No frameworks, no bundlers, no new dependencies, no tests (per user decision).

**Spec:** This file (plan created from conversation analysis; the repo analysis is the spec's source).

## Global Constraints

- Preserve ALL data: 315 block files stay untouched in `data/`; `Схема 0Y12-z22.html` untouched.
- Preserve ALL functionality: grid render, click-to-mark stitches, persistence, key table + shopping list.
- No test suite in this repo (user decision). Verification = curl checks + browser checklist.
- No new npm dependencies.
- Frontend hardcodes nothing but relative paths; API on same origin.

## Review Focus

- Migration must not lose or reorder a single stitch: 315 blocks × 100 cells, cell-by-cell equality with source files.
- Toggle persistence: after reload, marks must survive; debounced writes must not lose the last click (flush on pagehide).
- Static file serving must refuse paths escaping `public/` (`/../`, encoded `%2e%2e`).
- Old data files must remain readable by the migration script re-run (idempotent or harmless re-run).
